# HDP 2026 User Manual

Project: Kerala CMO HDP Portal (Hundred Days Programme)

This manual explains how each role uses the portal for daily operations.

## 1. Purpose

The HDP portal supports end-to-end programme tracking:

- Project creation and governance
- Indicator-level progress updates
- Evidence upload (images, videos, documents)
- Verification and approval workflow
- Public progress visibility

## 2. User Roles

The system supports these role groups:

- Admin: manages users, projects, master data, and audits
- OSD Admin: executive monitoring dashboard
- Nodal Officer: submits and updates project progress
- Verification Officer: validates submissions
- Public User: views published progress data

## 3. Access and Login

### Login

1. Open the login page.
2. Enter Login Name and Password.
3. Click Sign In.
4. You will be redirected automatically to your role home.

### If login fails

- Check Login Name for typing errors.
- Confirm CAPS LOCK is off.
- If multiple failed attempts occur, your account may be temporarily locked.
- Contact Admin for account assistance.

### Password management

- Forgot password: use Forgot Password from login screen.
- Change password: available after login in role-specific settings/profile areas.

## 4. Role-Wise Workflows

## 4.1 Admin Workflow

Primary areas:

- Dashboard
- Projects management
- Users management
- Audit logs
- Reports
- Change password

Typical daily flow:

1. Review dashboard for status overview.
2. Create or update projects.
3. Create or update user accounts and role assignments.
4. Review audit entries for sensitive actions.
5. Monitor report completeness and pending verification items.

Admin best practices:

- Keep role assignments accurate.
- Do not share credentials.
- Record reasons for sensitive operations where prompted.

## 4.2 OSD Admin Workflow

Primary area:

- OSD executive dashboard

Typical daily flow:

1. Open executive dashboard.
2. Review high-level KPIs and bottlenecks.
3. Follow up with departments/officers on delayed items.

Note: OSD Admin is intentionally focused on executive monitoring, not full admin CRUD operations.

## 4.3 Nodal Officer Workflow

Primary areas:

- Projects list
- Project indicators
- Indicator progress updates
- Evidence uploads (gallery/video/documents)

Typical daily flow:

1. Open Projects.
2. Select a project.
3. Open indicator list.
4. Add progress updates with current values.
5. Upload evidence for each update.
6. Submit complete and accurate data for verification.

Data quality checklist before submit:

- Indicator value is current and correct.
- Date and context are accurate.
- Evidence clearly supports the claimed progress.
- No duplicate uploads.

## 4.4 Verification Officer Workflow

Primary areas:

- Projects pending verification
- Indicator verification screens
- Submission history and evidence review

Typical daily flow:

1. Open Verify Projects.
2. Select project and indicator.
3. Review submitted values and all evidence.
4. Mark verified or send back for correction as applicable.
5. Complete project verification when all indicators are resolved.

Verification checklist:

- Submitted value matches evidence.
- Evidence quality is sufficient.
- Timeline is consistent with reporting period.
- Any rejection includes clear correction notes.

## 4.5 Public User Workflow

Primary areas:

- Home dashboard
- Department/district/sector progress pages
- Project detail and media views

Typical usage:

1. Open public home page.
2. Navigate by department, district, or sector.
3. View project-wise progress and media evidence.

## 5. Common Tasks

### Update profile information

1. Open Profile.
2. Edit allowed fields.
3. Save changes.

### Change password

1. Open Change Password screen.
2. Enter current password.
3. Enter and confirm new password.
4. Save.

Use a strong password with a mix of letters, numbers, and symbols.

### Upload evidence

1. Open target project indicator.
2. Open upload section.
3. Select valid file.
4. Add required metadata if prompted.
5. Submit and verify upload success message.

## 6. Data and Security Guidance

- Enter only verified official data.
- Avoid using personal or non-official devices where possible.
- Log out after each session, especially on shared systems.
- Do not share passwords by phone/chat/email.
- Report suspicious account activity to Admin immediately.

## 7. Troubleshooting

### Page not loading

- Refresh browser.
- Check internet connectivity.
- Retry after 1 to 2 minutes.

### Unauthorized access message

- You may be opening a route outside your role permissions.
- Return to your role dashboard and navigate from menu.

### Upload failure

- Check file size and format.
- Retry with stable internet.
- If repeated, contact Admin with timestamp and project/indicator details.

### Wrong redirection after login

- Sign out and sign in again.
- If issue persists, request Admin to verify your role mapping.

## 8. Support Escalation

When reporting an issue, include:

- Role and user login name
- Date/time of issue
- Module/page where issue occurred
- Exact error message (if visible)
- Project and indicator identifiers (if relevant)

First point of contact: Department Admin / Technical Admin.
